## Context

`0008` settles money classification: each line has **exactly one** category, so spending always
partitions cleanly and totals reconcile. But the user also classifies items along axes that are *not*
the money axis and that legitimately overlap:

- **Category-scoped tag** — meaningful only within one category. *Fruit* under *Food P1*; you would
  never tag a taxi "Fruit". A scoped tag is effectively a sub-classification of its category.
- **Global tag** — meaningful across any category. *For Happiness* can sit on a restaurant meal
  (Food), a video game (Entertainment), or a gift (Household).

Tags give the extra reporting axes ("how much Fruit", "how much For Happiness this year") without
disturbing the category partition. Because a tag must know whether/where it is scoped, tags are a
**managed vocabulary**, not free-text strings.

## Scope

In:

- `Tag` aggregate: name, scope (`CategoryId?`), active/archived lifecycle — parallel to `Category`.
- `ExpenseLine.TagIds` (0..n), additive to the `0008` line.
- Scope-compatibility rule enforced when recording/correcting an expense.
- Tag CRUD-ish surface (create, rename, archive) + a seed set.
- Tag suggestion folded into autocomplete (`ItemSuggestion.TagIds`).
- Per-line tag picker in `/add`, filtered to *global ∪ tags scoped to that line's category*.

Out:

- Tag-based **report screens** (Dapper analytics + UI land with the monthly summary slice).
- Hierarchical tags / tags-of-tags, tag colours, tag merge. Not requested; not built.
- AI tag inference (Insights, V2+).

## Decisions

### D1 — `Tag` is a small managed aggregate, parallel to `Category`

```
Tag (aggregate root)
  Id      : TagId
  Name    : string                 // required, bounded; case-insensitive-unique per scope
  Scope   : CategoryId?             // null = global; non-null = scoped to that category
  Status  : TagStatus { Active, Archived }   // soft-delete, mirrors Category
```

Scope is just a nullable `CategoryId` — no polymorphic hierarchy. Lifecycle mirrors `Category`
(`Create` / `Rename` / `Archive`, events `TagCreated` / `TagRenamed` / `TagArchived`). A scoped tag
referencing a category is an intra-module reference (both in the Expenses module); no cross-schema FK.

**Uniqueness (C3):** names are **case-insensitive unique within a scope** — at most one "Fruit" scoped
to Food, but a Food-scoped "Fruit" and a global "Fruit" are distinct rows. Enforced by the create/rename
command path (the only writers); a partial unique index can back it later if needed, but isn't required
for single-tenant correctness.

**No DB foreign keys (C1):** `Tag.Scope` is stored as a **plain converted `category_id` column with no
DB FK**, matching the convention `0008` chose for `expense_line.category_id`
(`ExpenseConfiguration` — "id-reference convention… referential integrity is held by the app").
Categories and tags are archived-never-deleted, so the validating handler + soft-delete hold integrity;
adding real FKs here would mix two conventions in one schema. Same applies to the join table (D2).

### D2 — The line references tags by id; scope is validated in the command handler

`ExpenseLine` stores `TagIds : IReadOnlySet<TagId>` (0..n). The compatibility rule —

> every tag on a line is `Active`, and is either global (`Scope == null`) or scoped to the line's own
> category (`Scope == line.CategoryId`)

— spans the `Tag` aggregate, so it is enforced in the `RecordExpense` / `CorrectExpense` **handler**
(which has the `Tag` repository), not inside `Expense`. The aggregate keeps tags as opaque
references, exactly as it already treats `CategoryId`. A violation surfaces as the same
validation-error path as other command failures.

This **mirrors the existing category rule** — `EnsureActiveCategoriesAsync` already runs on both
`Record` *and* `Correct` (`ExpenseHandlers`), so tag validation slots into the same pass (batch-load
the distinct referenced tags once) via an `EnsureCompatibleTagsAsync` sibling called from both handlers.

**Known limitation (C2), accepted not fixed here:** because validation runs on `Correct` too, editing
*any* field of an old expense whose line carries a since-archived classifier (category **or** tag) is
rejected. This friction already exists for categories in `0008`; `0009` deliberately inherits the same
behavior rather than diverging. Revisit holistically (grandfather already-present archived classifiers
on correction) when expense-edit UX lands — **out of scope for `0009`**.

**Persistence of `TagIds` (the join table):** `ExpenseLine` is a regular child entity post-`0008`
(`HasMany/WithOne`, shadow `expense_id`), so `TagIds` maps as an **`OwnsMany` collection of a tiny
`LineTag` value** holding one `TagId` → table `expenses.expense_line_tags`, composite key
`(expense_line_id, tag_id)`. `tag_id` is a plain converted column with **no EF navigation to the `Tag`
aggregate and no DB FK** (C1) — preserving the reference-other-aggregates-by-id rule. Read models join
on the id explicitly (LINQ/Dapper), never via a navigation.

### D3 — Suggestion remembers tags too

`0008`'s `ItemSuggestion(Text, CategoryId, Unit?)` gains `TagIds`: picking "cheese" lights its
category, pre-selects grams, **and** pre-selects its remembered tags (e.g. *Dairy* scoped to Food),
sourced from the most-recent line with that item name — still one round trip. A suggested tag that is
no longer scope-compatible (item's remembered category differs from the now-chosen category) is
dropped client-side before submit.

### D4 — Tag picker is filtered by the line's category

In `/add`, the per-line tag picker offers **global tags ∪ tags scoped to the chosen category**, so a
user is never shown "Fruit" on a Household line. Changing a line's category re-filters its tag options
and drops any now-incompatible scoped tags already picked (mirrors the currency re-round in `0008`).

### D5 — Inline tag creation (resolves OQ1)

Typing a name with no match in the picker offers **create-inline**. The new tag defaults to
**scoped to that line's current category** (the common case is a sub-classification, e.g. typing
"Berries" on a Groceries line), with a **toggle to make it global**. The create goes through the same
`CreateTag` command + case-insensitive-per-scope uniqueness check as the management API (D1 / C3) — a
collision returns the existing tag rather than erroring, so the picker just selects it. No separate
"quick create" path; the form calls the same `IExpensesApi.CreateTagAsync` and then selects the result.

## Domain model

Additions to `0008`:

```
ExpenseLine (child entity)             // 0008 fields, plus:
  TagIds : IReadOnlySet<TagId>         // 0..n; persisted as OwnsMany LineTag → expense_line_tags (D2)
```

```
Tag (aggregate root)                   // new; see D1
ExpenseLineDraft(... , IReadOnlySet<TagId> TagIds)   // 0008 draft gains TagIds
```

**Invariants**

- (handler) every line tag is `Active` and scope-compatible with the line's category — D2.
- (`Tag`) name non-empty and bounded; case-insensitive unique per scope (C3); archived tags are not
  destructively removed.

**Events**

- `TagCreated(TagId, string Name, CategoryId? Scope)`, `TagRenamed(TagId, string Old, string New)`,
  `TagArchived(TagId)`.
- No change to `ExpenseRecorded` / `ExpenseCorrected` — tags are an internal classification, not
  cross-module payload (same reasoning as `0008` D6 for categories).

## Public surface

- **Contracts:**
  - Tag management DTOs on `IExpensesApi` (create/rename/archive) + `IExpensesQueries.ListTagsAsync`
    (optionally filtered by category for the picker).
  - `ExpenseLineDto` gains `TagIds : IReadOnlyList<Guid>`.
  - `ItemSuggestion` gains `TagIds : IReadOnlyList<Guid>`.
- **Schema (no DB FKs — C1):** `expenses.tags (id, name, scope_category_id NULL, status)` —
  `scope_category_id` is a plain converted id column, no FK. `expenses.expense_line_tags
  (expense_line_id, tag_id)` join, PK `(expense_line_id, tag_id)`; `expense_line_id` is the owning-line
  key (cascade with the line), `tag_id` a plain converted id column, no FK. Integrity is app-enforced
  via the validating handler + soft-delete, matching `0008`'s `expense_line.category_id`.
- **Host:** `AddExpense.razor` per-line tag picker (D4) + inline create (D5). Still references Contracts only.

## Resolved questions

- **On-the-fly tag creation** → resolved in **D5**: inline create, default scoped-to-the-line's-category
  with a global toggle, through the same `CreateTag` command + per-scope uniqueness as the management API.
- **Seed set** → ships on an empty DB alongside the `0006` starter categories (extend
  `ExpensesMigrationService`, guarded on an empty `tags` table):
  - **Scoped to `Groceries`:** `Fruit`, `Vegetables`, `Dairy`.
  - **Global:** `For Happiness`, `Gift`, `Essential`.

  Anonymized starter taxonomy only; rename/archive/extend via the management API (D1). The scoped seeds
  resolve their `scope_category_id` from the just-seeded `Groceries` category id.

## Verification

- **Domain (unit):** `Tag` create/rename/archive + name bounds; `ExpenseLine` accepts a tag set.
- **Application (unit):** scope validation — a scoped tag on a mismatched-category line is rejected; a
  global tag is accepted anywhere; an archived tag is rejected.
- **Integration (Testcontainers Postgres):** record an expense whose lines carry mixed scoped/global
  tags; assert the `expense_line_tags` rows round-trip (and cascade-delete with the line); `ListTags`
  category filter returns globals ∪ scoped; `SuggestItems` returns remembered tags; inline `CreateTag`
  collision returns the existing tag (D5).
- **Manual:** `/add` — pick a category, see only that category's scoped tags + globals; switch category
  and watch incompatible tags drop; confirm a remembered item re-lights its tags.
- **Build gate:** `dotnet build` clean under warnings-as-errors.
