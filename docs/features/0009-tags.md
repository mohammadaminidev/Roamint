# 0009 — Expenses module: tags (scoped + global)

**Status:** Proposed — design under review; no code yet
**Depends on:** `0008` (line carries exactly one `CategoryId`; tags layer on top of that line)
**Lands in (planned):**
`src/Modules/Expenses/Roamint.Expenses.Domain/` (`Tag` aggregate; `ExpenseLine.TagIds`),
`src/Modules/Expenses/Roamint.Expenses.Application/` (tag commands/queries; scope validation in `RecordExpense`),
`src/Modules/Expenses/Roamint.Expenses.Infrastructure/` (`tags` + `expense_line_tags` tables, read models, seed),
`src/Modules/Expenses/Roamint.Expenses.Contracts/` (tag DTOs; `ItemSuggestion.TagIds`),
`src/Bootstrap/Roamint.Web/Components/Pages/AddExpense.razor(.css)` (per-line tag picker),
`tests/Modules/Expenses/...`

## Context

`0008` settles money classification: each line has **exactly one** category, so spending always
partitions cleanly and totals reconcile. But the user also classifies items along axes that are *not*
the money axis and that legitimately overlap:

- **Category-scoped tag** — meaningful only within one category. *Fruit* under *Food P1*; you would
  never tag a taxi "Fruit". A scoped tag is effectively a sub-classification of its category.
- **Global tag** — meaningful across any category. *For Happiness* can sit on a restaurant meal
  (Food), a video game (Entertainment), or a gift (Household).

Tags give the extra reporting axes ("how much Fruit", "how much For Happiness this year") without
disturbing the category partition. Because a tag must know whether/where it is scoped, tags are a
**managed vocabulary**, not free-text strings.

## Scope

In:

- `Tag` aggregate: name, scope (`CategoryId?`), active/archived lifecycle — parallel to `Category`.
- `ExpenseLine.TagIds` (0..n), additive to the `0008` line.
- Scope-compatibility rule enforced when recording/correcting an expense.
- Tag CRUD-ish surface (create, rename, archive) + a seed set.
- Tag suggestion folded into autocomplete (`ItemSuggestion.TagIds`).
- Per-line tag picker in `/add`, filtered to *global ∪ tags scoped to that line's category*.

Out:

- Tag-based **report screens** (Dapper analytics + UI land with the monthly summary slice).
- Hierarchical tags / tags-of-tags, tag colours, tag merge. Not requested; not built.
- AI tag inference (Insights, V2+).

## Decisions

### D1 — `Tag` is a small managed aggregate, parallel to `Category`

```
Tag (aggregate root)
  Id      : TagId
  Name    : string                 // required, bounded, unique-ish per scope
  Scope   : CategoryId?             // null = global; non-null = scoped to that category
  Status  : TagStatus { Active, Archived }   // soft-delete, mirrors Category
```

Scope is just a nullable `CategoryId` — no polymorphic hierarchy. Lifecycle mirrors `Category`
(`Create` / `Rename` / `Archive`, events `TagCreated` / `TagRenamed` / `TagArchived`). A scoped tag
referencing a category is an intra-module reference (both in the Expenses module); no cross-schema FK.

### D2 — The line references tags by id; scope is validated in the command handler

`ExpenseLine` stores `TagIds : IReadOnlySet<TagId>` (0..n). The compatibility rule —

> every tag on a line is `Active`, and is either global (`Scope == null`) or scoped to the line's own
> category (`Scope == line.CategoryId`)

— spans the `Tag` aggregate, so it is enforced in the `RecordExpense` / `CorrectExpense` **handler**
(which has the `Tag` repository), not inside `Expense`. The aggregate keeps tags as opaque
references, exactly as it already treats `CategoryId`. A violation surfaces as the same
validation-error path as other command failures.

### D3 — Suggestion remembers tags too

`0008`'s `ItemSuggestion(Text, CategoryId, Unit?)` gains `TagIds`: picking "cheese" lights its
category, pre-selects grams, **and** pre-selects its remembered tags (e.g. *Dairy* scoped to Food),
sourced from the most-recent line with that item name — still one round trip. A suggested tag that is
no longer scope-compatible (item's remembered category differs from the now-chosen category) is
dropped client-side before submit.

### D4 — Tag picker is filtered by the line's category

In `/add`, the per-line tag picker offers **global tags ∪ tags scoped to the chosen category**, so a
user is never shown "Fruit" on a Household line. Changing a line's category re-filters its tag options
and drops any now-incompatible scoped tags already picked (mirrors the currency re-round in `0008`).

## Domain model

Additions to `0008`:

```
ExpenseLine (owned entity)             // 0008 fields, plus:
  TagIds : IReadOnlySet<TagId>         // 0..n
```

```
Tag (aggregate root)                   // new; see D1
ExpenseLineDraft(... , IReadOnlySet<TagId> TagIds)   // 0008 draft gains TagIds
```

**Invariants**

- (handler) every line tag is `Active` and scope-compatible with the line's category — D2.
- (`Tag`) name non-empty and bounded; archived tags are not destructively removed.

**Events**

- `TagCreated(TagId, string Name, CategoryId? Scope)`, `TagRenamed(TagId, string Old, string New)`,
  `TagArchived(TagId)`.
- No change to `ExpenseRecorded` / `ExpenseCorrected` — tags are an internal classification, not
  cross-module payload (same reasoning as `0008` D6 for categories).

## Public surface

- **Contracts:**
  - Tag management DTOs on `IExpensesApi` (create/rename/archive) + `IExpensesQueries.ListTagsAsync`
    (optionally filtered by category for the picker).
  - `ExpenseLineDto` gains `TagIds : IReadOnlyList<Guid>`.
  - `ItemSuggestion` gains `TagIds : IReadOnlyList<Guid>`.
- **Schema:** `expenses.tags (id, name, scope_category_id NULL FK → categories, status)`;
  `expenses.expense_line_tags (expense_line_id FK, tag_id FK)` join. Both intra-schema FKs.
- **Host:** `AddExpense.razor` per-line tag picker (D4). Still references Contracts only.

## Open questions

- **On-the-fly tag creation:** when a user types a tag that doesn't exist, do we create it inline, and
  is a new tag global or scoped-to-the-current-category by default? Leaning: inline create, default to
  *scoped to the current line's category* (the common case is a sub-classification), with a global
  toggle. UI detail — settle in this slice's UI pass, not domain-blocking.
- **Seed set:** which starter tags ship on an empty DB (parallels the `0006` starter categories)? Needs
  a short anonymized list.

## Verification

- **Domain (unit):** `Tag` create/rename/archive + name bounds; `ExpenseLine` accepts a tag set.
- **Application (unit):** scope validation — a scoped tag on a mismatched-category line is rejected; a
  global tag is accepted anywhere; an archived tag is rejected.
- **Integration (Testcontainers Postgres):** record an expense whose lines carry mixed scoped/global
  tags; assert the join table + FKs; `ListTags` category filter; `SuggestItems` returns remembered tags.
- **Manual:** `/add` — pick a category, see only that category's scoped tags + globals; switch category
  and watch incompatible tags drop; confirm a remembered item re-lights its tags.
- **Build gate:** `dotnet build` clean under warnings-as-errors.
